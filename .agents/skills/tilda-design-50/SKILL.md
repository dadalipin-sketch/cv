# Tilda: от задачи к авторскому сайту

## Приоритеты

Актуальные указания пользователя выше этого навыка. Не добавлять по умолчанию мелкие декоративные рубрикаторы, номерные подписи разделов, микротеги, перечни направлений капсом и дублирующие подписи карточек. Только по явной просьбе. Содержательные заголовки, поля форм, цены, навигацию и необходимые пояснения сохранять. Ранее запрошенную интерактивность не удалять без причины.

Не приравнивать «дорогой дизайн» к чёрному фону, частицам, огромному тексту или множеству эффектов. Выбирать композицию, изображения и поведение под продукт. Для текста от имени Валерии применять её копирайтерский навык, если доступен. Не выдумывать кейсы, метрики, отзывы, сроки и гарантии прибыли.

## Сначала прочитать

- `references/patterns.md`: выбор подхода и реализация в Tilda.
- `references/projects-50.md`: 50 индивидуальных карточек, наблюдения и ограничения.
- `references/implementation.md`: Zero Block, код, MCP, адаптивы и проверка.
- `references/sources.json`: происхождение выборки и технические наблюдения.

Исследование выполнено 20.11.2026. Это визуально-структурный обзор 50 изображений из галереи и проверка доступного исходного HTML, а не полный интерактивный аудит. Два сайта дали 404/503. Движение, мобильные состояния, формы, оплаты и реальные показатели не проверены. Не превращать гипотезы в установленные факты.

## Рабочий процесс

1. Восстановить из переписки задачу, аудиторию, продукт, целевое действие, известные материалы и ограничения. Не повторять уже отвеченные вопросы. Уточнять только то, без чего нельзя принять важное решение.
2. Составить путь посетителя: что он должен понять, увидеть как подтверждение и сделать дальше. Для каждого раздела записать одну задачу. Объединить повторяющиеся блоки.
3. Выбрать 3–5 релевантных проектов из реестра: один для структуры, один для визуального языка, один для подачи доказательств. Назвать, какой принцип переносится. Не копировать чужие тексты, фотографии, логотипы или композицию целиком.
4. Определить направление: спокойное предметное, редакционное, выразительное событийное, техническое B2B либо авторское портфолио. Собрать собственную систему типографики, сетки, изображений, цветов и действий.
5. Подготовить текстовый прототип с реальным содержанием. Заголовок сообщает предложение; кнопка объясняет следующее действие. Уточнить неизвестные факты, вместо заполнения вымыслом.
6. Спроектировать первый экран и один характерный внутренний блок на desktop и mobile. Затем распространить систему на страницу. Избегать одинаковой сетки карточек в каждом разделе.
7. Разделить реализацию: стандартные блоки Tilda для поддерживаемых функций; Zero Block для авторской композиции; дополнительный код только для оправданных нестандартных эффектов. Если пользователь требует Zero Block, сохранить редактируемые тексты, картинки и кнопки нативными элементами.
8. Собрать и проверить по `implementation.md`. Показать именно сделанное: макет, код для вставки, проект в Tilda или опубликованную страницу. Не называть HTML внутри T123 нативным Zero Block.
9. Отчитаться кратко: результат, ссылка, проверенные сценарии, незавершённые подключения. Наличие навыка не означает наличие доступа к Tilda.

## Критерии композиции

- Один доминирующий визуальный акцент на экран. У крупного изображения должна быть содержательная роль.
- Различать контраст размера, цвета и плотности. Не усиливать всё одновременно.
- Привязывать асимметрию к общей сетке. Сохранять выравнивание текстовых колонок и ясный порядок чтения.
- Чередовать обзор и подробности: общий вид → конкретный пример → объяснение → действие.
- Короткий hero, читаемые абзацы, доказательства рядом с обещаниями. В портфолио быстро переходить к работам.
- Типографика с кириллицей и лицензией. Начальный ориентир: основной текст 16–20 px, мобильный 16–18 px; проверять фактическое чтение, не считать эти числа обязательным шаблоном.
- Цвета и шрифты не заимствовать механически из галереи. Контраст обычного текста проверять на 4.5:1, крупного на 3:1.
- Огромный заголовок не должен прятать смысл или занимать несколько пустых мобильных экранов.

## Motion

Анимация должна объяснять связь, состояние или пространственное перемещение. Не утверждать, что конкретный эффект увиден в статичном референсе. Начинать со штатных возможностей Tilda, затем оценивать custom JS. Для сцен между секциями: прогресс от scroll, обратимость, отсутствие захвата прокрутки, обход текста, отключение вне экрана, ограничение нагрузки, pause и reduced motion. На touch не зависеть от hover. Контент доступен без декоративного JS.

## Definition of done

Готовый маршрут посетителя; проверенные ссылки; рабочие или явно обозначенные демонстрационные формы; читабельный mobile; реальные материалы; понятный способ редактирования; сохранены настройки SEO; проверены загрузка, фокус и reduced motion; конкретно перечислены ограничения проверки. Галерейная эстетика не заменяет эти условия.
